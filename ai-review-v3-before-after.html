自前のプロンプト

Claude 側（own-review）

私たちが書いたプロンプト prompts/own-review.md（約 120 行）の本文を、そのまま claude -p に渡す。Claude Code の /code-review などのスラッシュコマンドは使わない（公式版に指示を足したものでもない）。

claude -p "<own-review.md の本文>" \
  --model claude-opus-5-5 --effort high \
  --setting-sources "" --safe-mode ...

理由: 公式 /code-review は素の状態で Opus 5.5 が 0.855、Opus 5 が 0.491。ECC 版と公式版の見落とし・止めすぎを分析して自前で書き、v5 は確認用データで 1.000。昇格の own-security も同じく自前のプロンプト。

純正コマンドのまま

Codex 側（codex-review）

Codex CLI の純正 review 機能をそのまま使う。独自の指示やプロンプトは一切渡さない。

codex exec review --base origin/main \
  -m gpt-6-sol -c model_reasoning_effort=high \
  -c sandbox_mode=read-only ...

理由: 純正のままで 0.964 と十分に高く、自前のプロンプトを渡すと 0.800 に下がった。

v2 では、Claude 側は「公式 /code-review」のつもりが、実際は第三者製の ECC のコマンドが動いていた（他人のコマンド）。v3 はスラッシュコマンドに頼らないので、コマンドの上書きの影響を受けない。

3. 仕組み（v3 の機構）

3.1 レビュアーの構成

名前種類中身モデル / effortいつ
own-review自前のプロンプト同梱の自前観点（v5）。変更ファイルごとの判定表・段つきの指摘・3 段の結論Opus 5.5 / high毎回
codex-review純正コマンド純正 codex exec review（独自の指示なし、read-only サンドボックス）GPT-6 Sol / high毎回
own-security自前のプロンプトセキュリティ専用観点。攻撃面の一覧 → 経路の確認 → 判定Opus 5.5 / high昇格時・--deep
own-review-fable自前のプロンプトown-review と同じ観点を別のモデルでFable 5.1 / high--deep
codex-astra純正コマンド純正 review を別のモデルでGPT-6 Astra / high--deep

3.2 結論の決まり方（下限）

生の出力→下限（floor）→最終 = 下限・エージェントの判断・項目の段の最も重いもの
  • own-* は最後の行の VERDICT: X を読む。無ければ「結論」の節の最も重い語（止める側）
  • Codex は行頭の優先度 [P0/P1] → BLOCK、[P2/P3] → MUST-ADDRESS
  • 結論を読めない・判定表が欠けた・失敗や未導入で結果が無い → MUST-ADDRESS の自動項目
  • 読めた結果が 1 つも無い → BLOCK
  • レビュアーが MUST-ADDRESS 以上なのに、そのレビュアーの項目が無ければ記録を拒む（指摘を丸ごと落とさせない）

3.3 MUST-ADDRESS の片づけ（C 案）

  • 直す: 修正して commit し、新しい HEAD で再実行。同じ指摘が出なければ「再レビュー済み」として引き継ぐ
  • 直さない: コードで確かめられる理由を記録（「たぶん大丈夫」「今は起きない」は不可）→ 作業の文脈を持たない別のサブエージェントが「理由は誤っている前提」で反証を探す → 成り立てば upheld
  • 高リスク（昇格ルールのパス・注入型・セキュリティの指摘）: upheld の後、ユーザー自身が端末で resolve-item.sh --approve-human を実行し ID を打ち込む。AI は代行しない
  • BLOCK は直すしかない

3.4 昇格（深掘りを足す条件）

  • A: 高リスクのパス（認証・決済・スキーマ・CI・Dockerfile など）
  • B: 危険な API の追加行（eval( など）
  • C: 規模（ファイル数・追加行数の上限超え）
  • D: どれかのレビュアーがセキュリティの指摘を出した（記録時にも機械で要求）
  • escalation.json の判定を下限にし、エージェントの --escalate false で打ち消せない。スキップはユーザーが明示したときだけ（記録に残る）

3.5 隔離と権限（レビュー対象に乗っ取られない）

  • Claude は --setting-sources "" --safe-mode --strict-mcp-config。ユーザーやレビュー対象の設定・フック・CLAUDE.md・MCP を読まない
  • 道具は Read・Grep・Glob と読み取り系の git（diff・show・log など）だけ。git -c・--output・--no-index などは拒否
  • Codex は -c notify=[] -c mcp_servers={}。レビュー対象に .codex/ があれば起動しない
  • 秘密情報のファイルが差分にあれば、外部モデル（Codex）を起動しない
  • pre-push の python は -I で cwd を読み込まない
  • 効いているかは probe-permissions.sh が実機で確かめる（印のファイルが作られないこと）

3 段の結論と片づけv3 試作は BLOCK だけで止めすぎた（バグのない 18 件中 15 件）。止めない指摘を「直すか理由を検証」にすると、品質を落とさず止めすぎを防げた

5. 残っている限界

  • 人の承認と記録は、作業中の AI が書けるファイル（latest.json）にある。端末での ID 入力で誤って書く経路は塞いだが、技術的に完全には強制できない（手順と記録で担保）
  • 「後回し（Issue 化）」の片づけ方が無い。本物だが急がない指摘も、直すか理由を検証するしかない
  • Medium 以下の残りの指摘（Codex が AGENTS.md を読む、.review-reports のシンボリックリンクなど）
  • コストは未計測。所要時間は通常 3.5〜7 分、深掘り込み 7〜15 分、--deep 7.5〜15 分
  • クラウド（claude.ai/code）では Codex CLI が無いので動かない。クラウドは /code-review で代替し、正式なゲートはローカルで通す
